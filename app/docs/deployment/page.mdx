# Deployment

Production deployment for FluxKit spans the public website, the docs section, and the application services that power authenticated product features.

## Deployment checklist

<Steps>
### Build and validate locally

Run the production build for the marketing site and confirm the docs routes render correctly.

### Configure production environment variables

Set canonical URLs, auth secrets, billing credentials, email settings, monitoring DSNs, analytics identifiers, and Convex deployment targets.

### Provision external services

Create production resources for backend, billing, email, and monitoring before moving real traffic.

### Verify operational flows

Smoke-test sign in, invite acceptance, plan changes, notification delivery, and marketing-to-docs navigation on the deployed environment.
</Steps>

## Launch guidance

- Keep marketing and docs on the same primary domain whenever possible.
- Use preview deployments to validate redirects and callback URLs.
- Add uptime, error, and payment-failure monitoring before opening the product publicly.

<Callout type="warning">
  Successful deployment is not just a green build. It includes verified auth
  flows, billing behavior, notification delivery, and observability.
</Callout>
